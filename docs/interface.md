# Интерфейс

Единственный интерфейс приложения — dashboard на Blazor WebAssembly и MudBlazor,
поверх ASP.NET Core API и SignalR.

Прежний интерфейс (`Frontend.Legacy`) удалён вместе с маршрутами `/legacy`.

## Внешний вид и функциональные цвета

Панель по кнопке палитры позволяет выбрать тёмную/светлую тему, один из шести
акцентов, собственный HEX-цвет и плотность таблиц. Акцент хранится в cookie
`fc-accent` на год для всего приложения; тема и плотность — в localStorage
`fc-theme` и `fc-density`.

Сезонные темы живут в `Frontend.Shared/Seasons`. Каждая тема — класс с интерфейсом
`ISeasonalTheme`: ключ, название, ежегодное окно по дате (`SeasonalWindow`, может
переходить через Новый год), компонент украшений поверх страницы и компонент
значка вместо логотипа. `AddSeasonalThemes()` сам находит все реализации и
регистрирует их в DI списком; `SeasonalThemes` выбирает идущие сейчас по дате
браузера. Оболочка кабинетов и экран входа рисуют их через `SeasonalDecorations`
и `BrandMark`, не зная о конкретных темах.

Пока тема идёт, в панели внешнего вида есть её переключатель. Выключенные темы
хранятся в localStorage `fc-seasons-off` (старый `fc-halloween=off` переносится).
Хэллоуин (`HalloweenTheme`) идёт с 20 октября по 2 ноября: призраки и паук,
тыква вместо значка и на кнопке записи в очередь. Флагов развёртывания нет.

Акцент подстраивается для читаемости в обеих темах. Цвета статусов,
преподавателей и студентов сохраняют своё функциональное значение. В таблице
доработок показана буква преподавателя с его цветом; история доработки открыта
сразу. В очереди видны все текущие проверяющие и статус каждой строки.

Студент со статусом «пропущен» или «сдал» нажимает «Встать повторно» (и при закрытой самозаписи — она не пускает только новых): его новая
строка с бейджем «повторно» встаёт в конец ожидающих — после всех первых кругов при любой сортировке, а прошлый
круг остаётся в списке приглушённым («1-й круг»). «Взять следующего» берёт повторных только после первичных.
Строку прошлого круга можно открыть только для просмотра. Самозапись переключается в шапке очереди и в
«Управлении → Очереди» для любой очереди, в том числе заполненной по группам.

Порог опоздания («Опоздание после, мин») задаётся при создании очереди и в её шапке. Записавшиеся позже
ждут после пришедших вовремя; у них отметка «Опоздание N мин», и преподаватель может снять её кнопкой «Снять»
(уважительная причина) или вернуть. Студент видит отметки в таблице и подсказку про своё опоздание.

При проверке студента очередь атомарно закрепляет его за преподавателем:
другой преподаватель не может перехватить или завершить эту проверку. После
выхода из статуса проверки владелец очищается. Миграция базы для этого изменения
не требуется.

Перекличка начинается с создания отдельного события и выбора групп. Далее
показывается полный список занятия с кнопками «Есть/Нет», немедленным
сохранением, счётчиками и фильтром неотмеченных.

Также у каждого студента и администратора есть достижения. Одно из них можно сделать **активным** (в профиле:
открыть награду → «Сделать активным»): его значок показывается рядом с именем, а оформление применяется к
аватару (рамка, кольцо, свечение), имени, строке в таблице результатов и очереди, странице профиля (видят все)
и ко всему сайту у самого владельца (частицы поверх интерфейса). Достижение с пометкой «активно по умолчанию»
активно у владельца, пока он не выбрал другое. Вдохновлено бейджиками TeamSpeak.

Каталог и управление достижениями — одна страница «Достижения». Действия, на которые не хватает прав
(создание, изменение, архив — только супер-администратор), видны, но неактивны, с подсказкой «Недостаточно прав».
Редактор достижения — отдельная страница (`/admin/achievements/{id}`) с живым предпросмотром: конструктор
(цвета, градиенты, анимации, картинки рамки/узора/баннера/частицы) и поле своего CSS.

Свой CSS — ограниченный диалект, который проверяет сервер (`EffectCssCompiler`): правило начинается с поверхности
(`avatar`, `name`, `row`, `profile`, `hero`, `site`, `site i`), разрешены только перечисленные свойства, `@keyframes`,
`@media`, `@light`/`@dark`; картинки — только свои, через `image(frame|pattern|banner|decor|badge)`, без `url()`.
У строк таблицы нельзя менять геометрию: таблица виртуализирована и держит фиксированную высоту строки.
Эффекты отдаются одной таблицей стилей `/api/achievements/effects.css`, привязанной к `[data-fx="id достижения"]`;
любой пользователь может выключить их у себя в настройках оформления («Эффекты достижений»).

## Локальная проверка

```powershell
dotnet test FunAndChecks.slnx
dotnet publish FunAndChecks/FunAndChecks.csproj -c Release
```

Рабочий Dockerfile собирает API и интерфейс в одну публикацию.
