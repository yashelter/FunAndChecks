# Интерфейс

Единственный интерфейс приложения — dashboard на Blazor WebAssembly и MudBlazor,
поверх ASP.NET Core API и SignalR.

Прежний интерфейс (`Frontend.Legacy`) удалён вместе с маршрутами `/legacy`.

## Внешний вид и функциональные цвета

Панель по кнопке палитры позволяет выбрать тёмную/светлую тему, один из шести
акцентов, собственный HEX-цвет и плотность таблиц. Акцент хранится в cookie
`fc-accent` на год для всего приложения; тема и плотность — в localStorage
`fc-theme` и `fc-density`.

Сезонные темы живут в `Frontend.Shared/Seasons`. Каждая тема — класс с интерфейсом
`ISeasonalTheme`: ключ, название, ежегодное окно по дате (`SeasonalWindow`, может
переходить через Новый год), компонент украшений поверх страницы и компонент
значка вместо логотипа. `AddSeasonalThemes()` сам находит все реализации и
регистрирует их в DI списком; `SeasonalThemes` выбирает идущие сейчас по дате
браузера. Оболочка кабинетов и экран входа рисуют их через `SeasonalDecorations`
и `BrandMark`, не зная о конкретных темах.

Пока тема идёт, в панели внешнего вида есть её переключатель. Выключенные темы
хранятся в localStorage `fc-seasons-off` (старый `fc-halloween=off` переносится).
Хэллоуин (`HalloweenTheme`) идёт с 20 октября по 2 ноября: призраки и паук,
тыква вместо значка и на кнопке записи в очередь. Флагов развёртывания нет.

Акцент подстраивается для читаемости в обеих темах. Цвета статусов,
преподавателей и студентов сохраняют своё функциональное значение. В таблице
доработок показана буква преподавателя с его цветом; история доработки открыта
сразу. В очереди видны все текущие проверяющие и статус каждой строки.

При проверке студента очередь атомарно закрепляет его за преподавателем:
другой преподаватель не может перехватить или завершить эту проверку. После
выхода из статуса проверки владелец очищается. Миграция базы для этого изменения
не требуется.

Перекличка начинается с создания отдельного события и выбора групп. Далее
показывается полный список занятия с кнопками «Есть/Нет», немедленным
сохранением, счётчиками и фильтром неотмеченных.

## Локальная проверка

```powershell
dotnet test FunAndChecks.slnx
dotnet publish FunAndChecks/FunAndChecks.csproj -c Release
```

Рабочий Dockerfile собирает API и интерфейс в одну публикацию.
