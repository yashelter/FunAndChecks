# Посещаемость

Учёт посещаемости необязателен и включается отдельно для каждого предмета. Преподаватель
включает его в разделе «Посещаемость» либо «Управление → Предметы», затем создаёт занятие,
выбирая группы, дату, московское время и необязательное название. Полноценного расписания нет:
занятия, не заведённые в журнал, не считаются пропусками.

## Журнал и перекличка

- Сводный журнал: строки — студенты и сохранённые группы, столбцы — учтённые занятия.
  Фильтры предмета, группы и периода применяются кнопкой «Показать»; подпись таблицы показывает
  применённый период. Поиск, фильтр невыставленных отметок и сортировка по пропускам работают
  внутри загруженного журнала.
- XLSX использует тот же предмет, группу и применённый период. Поиск по фамилии и фильтр
  невыставленных отметок не сокращают экспорт: скачивается вся выбранная группа.
- Нажатие на дату или ячейку открывает перекличку. Нажатие на имя показывает историю за период.
- Отметки «Присутствовал», «Отсутствовал», «Не отмечен» сохраняются сразу. Сброс возвращает
  состояние «Не отмечен» и также сохраняет последнего автора и время изменения.
- «Оставшихся нет» требует подтверждения количества. Применяется ко всем доступным неотмеченным
  студентам занятия независимо от поиска и фильтров, не затрагивает остальные отметки.
- «Добавить студента» включает позднее зарегистрировавшегося подтверждённого студента одной
  из групп занятия. Запись появляется с состоянием «Не отмечен».
- Личная вкладка студента содержит только собственные отметки; выбор предметов включает
  предметы из его истории, даже после перевода, отвязки предмета или удаления назначения группы.

## Данные и права

Основные сущности — `AttendanceSession` и `AttendanceRecord`. Состав группы фиксируется
одновременно с созданием занятия. `AttendanceRecord.GroupId` и `GroupName` — снимок, без FK
на текущую группу; перевод студента и переименование группы не меняют прошлые записи.
Связующая таблица `AttendanceSessionGroups` хранит выбранные группы, включая пустые.
На пару занятие/студент приходится одна запись с составным первичным ключом.

Отключение учёта запрещает создание занятий, добавление студентов и изменение отметок;
просмотр, личная история и XLSX остаются доступны. Посещаемость не изменяет оценки,
баллы и очередь. «Не отмечен» не считается отсутствием, а отсутствие студента в составе
конкретного занятия отображается отдельно («·» в UI, «н/у» в XLSX).

Все административные операции проверяют ограничения и скрытие предмета. Запрет или скрытие группы блокирует
создание занятия для этой группы и изменение её исторических отметок; читать журнал можно,
аналогично существующим очередям. При массовой отметке проверяется весь пакет до сохранения.
Скрытые и запрещённые группы исключены из выбора и добавления студентов; их исторические
отметки доступны для чтения, но изменять их нельзя. Для изменения снова предоставьте доступ к группе.

Отметка содержит `MarkedByAdminId`, `UpdatedAt` и `Version` (GUID concurrency token).
Изменение с устаревшей версией возвращает HTTP 409; массовая операция откатывается целиком.
Удаление преподавателя обнуляет автора, сохраняя отметки. Удаление студента или предмета
каскадно удаляет соответствующие записи, как в существующих моделях оценок и сдач.

Дата/время хранится в UTC; в журнале, фильтрах и XLSX учебный день задаётся по Москве (UTC+3).
Начало и конец периода включительны; несколько занятий в один день — отдельные столбцы.

## API

Административные маршруты (`Admin`):

- `PUT /api/attendance/subjects/{subjectId}/settings` — `{ enabled }`.
- `GET /api/attendance/subjects/{subjectId}/groups` — доступные связанные группы.
- `GET /api/attendance/subjects/{subjectId}/journal?groupId=&from=&to=` — сводный журнал.
- `GET /api/attendance/subjects/{subjectId}/export?groupId=&from=&to=` — XLSX.
- `POST /api/attendance/subjects/{subjectId}/sessions` — `{ name?, startsAt, groupIds }`.
- `GET /api/attendance/sessions/{sessionId}` — состав, отметки и доступность изменения.
- `PUT /api/attendance/sessions/{sessionId}/students/{studentId}` — `{ status, version }`.
- `POST /api/attendance/sessions/{sessionId}/remaining-absent` — `{ students: [{ studentId, version }] }`.
- `GET /api/attendance/sessions/{sessionId}/available-students` — кандидаты для добавления.
- `POST /api/attendance/sessions/{sessionId}/students/{studentId}` — добавить в состав.

Маршруты студента (`User`):

- `GET /api/me/attendance/subjects` — текущие и исторические предметы.
- `GET /api/me/attendance/subjects/{subjectId}` — личная история.

`from` и `to` передаются в формате `yyyy-MM-dd`; `startsAt` — ISO 8601 UTC с `Z`.
Статусы: `0 = Unmarked`, `1 = Present`, `2 = Absent`.

Миграция `AddAttendance` добавляет таблицы и флаг `Subjects.AttendanceEnabled` с начальным
значением `false`. В существующих базах автоматическая миграция выполняется при запуске API
обычным механизмом приложения; тесты используют SQLite `EnsureCreated`.
