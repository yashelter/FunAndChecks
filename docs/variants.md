# Варианты

Преподаватель с доступом к предмету заводит **наборы вариантов**: например «ЛР 1–4» или «Курсовая».
У каждого набора свой пул, правило повторов и срок выбора. Студент берёт по одному варианту
в каждом наборе. Выдача идёт по правилу «кто первый — того и вариант».

## Интерфейс

### Преподаватель: «Варианты» (`/admin/variants`)

- Выбор предмета запоминается, как на остальных страницах (`CurrentSubject`).
- Набор создаётся кнопкой «Новый набор». Можно сразу задать:
  - название;
  - правило повторов;
  - открыт ли выбор;
  - срок по Москве;
  - диапазон номеров, не больше 500 за раз.
- У каждого набора две вкладки.
  - **Студенты**. Здесь показаны все активные студенты групп, связанных с предметом, кроме скрытых и запрещённых для преподавателя групп.
    - Вариант выдаётся, меняется или снимается через список в строке.
    - Пометка «занят» подсказывает, что по правилу набора вариант уже у другого студента.
    - Выдать занятый вариант всё равно можно.
    - Под списком видно, выбрал ли студент вариант сам или его выдал преподаватель.
    - Фильтры: группа, поиск по фамилии, «Без варианта».
  - **Варианты**. Пул набора:
    - номер, название, описание и число выдач;
    - добавление диапазоном или по одному варианту;
    - правка названия и описания;
    - удаление. Удалить можно только вариант, который никому не выдан.
- «Открыть выбор» и «Закрыть выбор» переключают выбор вручную. Если срок уже прошёл, открытие снимает его.
- В таблице результатов у каждого набора своя колонка «Вар.: {набор}» после колонки «Группа». Если наборов нет, колонок тоже нет.
- В карточке студента (диалог работы со студентом) есть последняя вкладка «Варианты». Там те же выдача и смена варианта по каждому набору предмета.

### Студент: «Варианты» (`/student/variants`)

Для каждого набора выбранного предмета показывается одно из четырёх состояний:

- **Вариант уже есть.** Показываются номер, название и описание, а также кто назначил вариант: сам студент или преподаватель.
- **Выбор открыт.** Показывается сетка вариантов, занятые варианты неактивны. Кнопка «Взять» просит подтверждения: выбор окончательный, поменять вариант может только преподаватель.
  - Если вариант успели занять, придёт ошибка `variant.taken`, и список перечитается.
- **Выбор закрыт или срок прошёл.** Показывается подсказка, что вариант назначит преподаватель.
- **Все варианты заняты.** Показывается предупреждение.

Когда преподаватель выдаёт или меняет вариант, студент получает уведомление `VariantAssigned` со ссылкой на `/student/variants`. Снятие варианта уведомления не создаёт.

## Правила

- **Повторы** (`VariantUniqueness`):
  - `AllowRepeats` — повторы разрешены;
  - `UniqueInSubject` — вариант достаётся одному студенту во всём наборе;
  - `UniqueInGroup` — вариант достаётся одному студенту внутри **текущей** группы. Снимок группы не хранится: после перевода студента вариант остаётся за ним.
- Смена правила действует на следующие выборы. Уже выданные повторы остаются.
- **Выбор открыт**, когда `ClaimsOpen && (ClaimDeadline is null || сейчас < ClaimDeadline)`. Срок хранится в UTC, в интерфейсе показывается по Москве (UTC+3).
- **Преподаватель** не ограничен ни правилом, ни сроком. Ему нужны доступ к предмету и группе студента, а группа студента должна быть связана с предметом. Иначе сервис отвечает `student.not_enrolled`.
- **Студент**:
  - видит и берёт варианты только в предметах своей группы;
  - получает один вариант на набор;
  - не видит имён других студентов, только флаг «занят».

## Данные

- `VariantSet` (`SubjectId`, `Name`, `Uniqueness`, `ClaimsOpen`, `ClaimDeadline`, `CreatedAt`). При удалении предмета удаляется каскадом.
- `Variant` (`VariantSetId`, `Number`, `Title?`, `Description?`):
  - номер уникален в наборе;
  - вариант удаляется каскадом вместе с набором.
- `VariantAssignment`:
  - составной ключ `(VariantSetId, StudentId)`, то есть один вариант на студента в наборе;
  - поля `VariantId`, `AssignedAt`, `AssignedByAdminId?`, `SelfClaimed`.
  - Внешний ключ на вариант — `NO ACTION`, а не `RESTRICT`. Postgres проверяет его в конце оператора, поэтому каскад от набора или предмета удаляет варианты и выдачи вместе. Удалить выданный вариант напрямую сервис не даёт (`variant.in_use`).
- **Гонки.** Выбор выполняется в `ExecuteSerializableAsync`. Если двое берут один уникальный вариант, повтор сериализуемой транзакции даёт проигравшему `variant.taken`. Двойной клик одного студента упирается в первичный ключ и даёт `variant.already_chosen`.
- **Аудит.** Изменения преподавателя попадают в журнал аудита (`VariantsController`, сущности `variant_set`, `variant`, `variant_assignment`). Выбор студента в аудит преподавателей не пишется.

Миграция `AddVariants` создаёт три таблицы и ничего не меняет в существующих.

## API

Преподаватель (`Admin`):

- `GET|POST /api/variants/subjects/{subjectId}/sets`. Тело POST: `{ name, uniqueness, claimsOpen, claimDeadline?, rangeFrom?, rangeTo? }`.
- `PUT|DELETE /api/variants/sets/{setId}`. Тело PUT такое же, диапазон игнорируется.
- `POST /api/variants/sets/{setId}/variants` — `{ number, title?, description? }`.
- `POST /api/variants/sets/{setId}/variants/range` — `{ from, to }`. Существующие номера пропускаются, ответ — число добавленных.
- `PUT|DELETE /api/variants/variants/{variantId}`. Тело PUT: `{ title?, description? }`.
- `GET /api/variants/subjects/{subjectId}/board` — наборы и строки студентов с их вариантами.
- `GET /api/variants/subjects/{subjectId}/students/{studentId}` — наборы глазами студента, для карточки.
- `PUT|DELETE /api/variants/sets/{setId}/students/{studentId}` — выдать (`{ variantId }`) или снять.

Студент (`Student`):

- `GET /api/me/variants/subjects/{subjectId}`.
- `POST /api/me/variants/sets/{setId}/claim` — `{ variantId }`.

Коды ошибок:

- `variant.claims_closed`
- `variant.already_chosen`
- `variant.taken`
- `variant.in_use`
- `variant.number_taken`
- `variant.not_found`
- `variant_set.not_found`
- `student.not_enrolled`

Значения `uniqueness`: `0 = AllowRepeats`, `1 = UniqueInSubject`, `2 = UniqueInGroup`.
